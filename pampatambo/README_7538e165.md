# Módulo TAMBO

Módulo de gestión de tambo (explotación lechera) para integrar en ERP existente (Node.js + HTML).

## Estructura

```
modulo-tambo/
├── config/              # Configuración (BD, módulo, constantes)
├── db/
│   ├── migrations/      # Scripts SQL de creación de tablas
│   └── seeds/           # Datos iniciales (categorías, razas, etc.)
├── models/              # Acceso a datos por entidad
├── controllers/         # Lógica de cada endpoint
├── routes/              # Definición de rutas Express
├── services/            # Lógica de negocio (cálculos, reglas)
├── middleware/          # Auth, validaciones
├── utils/               # Helpers
├── views/tambo/         # Vistas HTML (una carpeta por submódulo)
│   ├── rodeo/
│   ├── produccion/
│   ├── reproduccion/
│   ├── sanidad/
│   ├── alimentacion/
│   ├── pasturas/
│   ├── usina/
│   └── personal/
├── public/              # CSS/JS estáticos del módulo
└── tests/               # Pruebas
```

## Submódulos

1. **Rodeo** — animales, categorías, caravanas, genealogía
2. **Producción** — ordeñes diarias, litros, calidad (grasa, proteína, CCS)
3. **Reproducción** — servicios, preñeces, partos, secado
4. **Sanidad** — vacunas, tratamientos, diagnósticos
5. **Alimentación** — raciones, consumo, stock de alimentos
6. **Pasturas** — potreros, rotación, disponibilidad
7. **Usina** — remitos, entregas, liquidaciones
8. **Personal** — tamberos, turnos, tareas

## Integración con el ERP

- Montá las rutas en tu `app.js` principal:
  ```js
  app.use('/tambo', require('./modulo-tambo/routes'));
  ```
- Ejecutá las migraciones en `db/migrations/` en orden.
- Ajustá `config/database.js` a tu BD (Postgres/MySQL/SQLite/SQL Server).

## Publicación en Cloudflare

- La web estática publicada se sirve desde `public_protected/` (generada por ofuscación del JavaScript inline).
- Cada cambio que se sube a `main` publica automáticamente en Cloudflare Workers mediante Workers Builds (integración GitHub App de Cloudflare).
- El nombre del worker queda definido en `wrangler.jsonc`.
- Si usás Workers Builds, no hace falta mantener un workflow de deploy en GitHub Actions para este repositorio.
- `localhost:3000` es solo local y no se puede publicar en Cloudflare.
- URL pública por defecto: `https://pampatambo-erp.<tu-subdominio>.workers.dev`.
- Para dominio propio, configurá una ruta `custom_domain` en `wrangler.jsonc` (plantilla incluida) o desde el dashboard de Cloudflare.

## Inicio local recomendado

- Para evitar errores de licencia por abrir en `:5500`, iniciá local con:
  ```bash
  npm run start:auto
  ```
- Ese comando levanta el backend y abre automáticamente `http://127.0.0.1:3000/`.
- Si querés abrir también el generador de licencias automáticamente:
  ```bash
  $env:TAMBO_OPEN_GENERATOR=1; npm run start:auto
  ```
- En Windows también podés usar doble click:
  - `iniciar-local.bat` abre la app local.
  - `iniciar-local-con-generador.bat` abre app + generador de licencias.

## Protección de código (web y .exe)

- Para generar assets web ofuscados ejecutá:
  ```bash
  npm run protect:web
  ```
- Ese comando crea/actualiza `public_protected/` a partir de `public/`.
- Para compilar partes sensibles del ejecutable a bytecode (.jsc) ejecutá:
  ```bash
  npm run protect:bytecode
  ```
- Los comandos de build de Electron (`dist:basica`, `dist:profesional`, `dist:premium`) ejecutan automáticamente `npm run protect:web` + `npm run protect:bytecode` antes de empaquetar.
- El servidor usa `public_protected/` por defecto cuando existe; si no, hace fallback a `public/`.
- La firma y validación de licencias se hace en backend (`/tambo/license/sign` y `/tambo/license/verify`) para no exponer la clave secreta en frontend.
